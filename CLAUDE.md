# CLAUDE.md

## Repository Overview

**Project**: template-test
**Remote**: `mikenickles/template-test`

The repository holds two independent projects:

- **`breach-line/`** — *Breach Line*, an original round-based tactical FPS
  built with **Godot 4.7.2** (GDScript, Jolt physics, Forward+ renderer).
  `breach-line/DEVELOPMENT.md` is the source of truth for its architecture,
  phase history, decisions, known issues and next steps — read it first.
- Repository root — a small Astro + Tailwind blog (`src/`, `astro.config.mjs`).

## Breach Line commands (run from `breach-line/`)

```
# Play:        godot --path .            (or open project.godot in Godot 4.7)
# Test:        tools/run_tests.sh [filter]   (headless; fails on script errors)
# Compile:     tools/check_scripts.sh
# Balance:     godot --headless --fixed-fps 60 --path . res://tools/sim/balance_sim.tscn -- --rounds=36
# Perf:        godot --headless --fixed-fps 60 --path . res://tools/sim/perf_probe.tscn
# Screenshots: tools/screenshot.sh <dir> [views]   tools/game_shot.sh <png> [frames] [flags]
# Export:      tools/export.sh [linux|windows|all]  (needs 4.7.2 export templates)
# Assets:      python3 tools/texgen.py | tools/sfxgen.py | tools/decalgen.py; python3 tools/fix_imports.py
```

Conventions: gameplay code lives in `breach-line/src/<area>/`, tuning in
`data/weapons/*.tres` and `MatchConfig`, map content in
`src/map/layouts/sawtooth_layout.gd`. Only `PlayerBrain` reads `Input`;
bots and players share `CombatIntent`. Add a `tests/test_*.gd` suite for new
systems. All art/audio is generated by the scripts in `tools/` — keep it
original.

## Development Workflow

### Branching

- Feature branches should be created from the default branch.
- Use descriptive branch names (e.g., `feature/add-auth`, `fix/login-bug`).

### Commits

- Write clear, concise commit messages describing **why** the change was made.
- Keep commits focused on a single logical change.

### Code Quality

See "Breach Line commands" above for the game. The Astro site uses
`npm run dev` / `npm run build`.

## Conventions for AI Assistants

- Read existing code before proposing changes.
- Keep changes minimal and focused on the task at hand.
- Do not add features, abstractions, or refactors beyond what is requested.
- Run tests and linters after making changes (once configured).
- Do not commit secrets, credentials, or `.env` files.
