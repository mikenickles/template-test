# Breach Line — Development Log

Original round-based tactical FPS (Godot 4.7, GDScript). One map, two teams,
bomb objective, economy, bots. This file is the single source of truth for
architecture, decisions, phase status, known bugs and next steps.

---

## 1. Quick start

| Task | Command (run from `breach-line/`) |
|---|---|
| Play | `godot --path .` (or open `project.godot` in the Godot 4.7 editor and press F5) |
| Run tests | `tools/run_tests.sh` (optional filter: `tools/run_tests.sh test_map`) |
| Regenerate textures | `python3 tools/texgen.py` |
| Regenerate sounds | `python3 tools/sfxgen.py` (needs `pip install scipy`) |
| Fix texture import settings | `python3 tools/fix_imports.py && godot --headless --path . --import` |
| Map screenshots | `tools/screenshot.sh <out_dir> [views=all] [quality] [frames]` |
| In-game screenshot | `tools/game_shot.sh <out.png> [frames] [--spawn=x,y,z,yaw]` |

Requirements: Godot **4.7.x** (standard build, not .NET). The project uses the
Jolt physics engine (built into 4.7) and the Forward+ renderer on desktop;
`rendering_method.mobile` is set to `mobile` for future phone builds.

Default controls: WASD move, mouse look, Space jump, Ctrl/C crouch, Shift
walk, LMB fire, RMB alt-fire/scope, R reload, E use (plant/defuse/pick up),
G drop, 1-5 slots, Q last weapon, wheel cycle, B buy menu, Tab scoreboard,
Esc pause.

## 2. Game design summary

- **Teams**: *Breachers* (attackers, carry the breach charge) vs *Wardens*
  (defenders). 5v5: the player plus four bots against five bots.
- **Round**: freeze/buy time → live (1:55) → optional bomb phase (40 s fuse)
  → round end. Attackers win by eliminating defenders or detonating the
  charge; defenders win by eliminating attackers before a plant, by running
  out the clock, or by defusing.
- **Match**: first to 7 round wins (max 12 rounds), sides swap at halftime
  (after round 6) with money reset.
- **Economy**: start money, win/loss rewards with escalating loss bonus,
  per-weapon kill rewards, plant/defuse bonuses, money cap.
- **Map**: *Sawtooth* — an original decommissioned rail-freight yard and
  foundry (sawtooth-roofed factory halls). Two bombsites (A: rail platform,
  B: foundry hall), mid street, long route, catwalk short route, culvert
  tunnel, defender rotations.
- All names (teams, weapons, map) and all content (geometry, textures,
  sounds) are original and generated by this repository's code.

## 3. Architecture

### 3.1 Principles

1. **One simulation for humans and bots.** A `Combatant`
   (`CharacterBody3D`) is driven only by a `CombatIntent` (move vector,
   absolute view angles, buttons). `PlayerBrain` fills the intent from
   keyboard/mouse; `BotBrain` fills it from AI. Movement, weapon handling and
   rules can't diverge between them, and bots are "fair" by construction.
2. **Input abstraction for mobile.** Only `PlayerBrain` touches `Input`.
   A future touch-controls source writes the same `CombatIntent`.
3. **Data-driven content.** Weapons are `WeaponData` resources
   (`data/weapons/*.tres`); the map is a declarative layout script consumed
   by a reusable `MapBuilder`; match rules live in a `MatchConfig` resource.
4. **Event bus, not webs of references.** Systems talk through the `Events`
   autoload (kills, damage, round flow, objective, UI announcements). HUD,
   audio, AI hearing and stats subscribe independently.
5. **Pure rules are separate from nodes** (`DamageModel`, `Economy`,
   recoil/spread math) so they are unit-testable headless.
6. **Everything testable headless.** `tests/` runs under `--headless` and
   includes full bot-vs-bot round simulations.

### 3.3 Autoload singletons

| Name | File | Responsibility |
|---|---|---|
| `Events` | `src/autoload/events.gd` | Global signal bus |
| `GameSettings` | `src/autoload/game_settings.gd` | Persisted settings (`user://settings.cfg`), input action registration, audio buses, quality presets |
| `Audio` | `src/autoload/audio_manager.gd` | Pooled 2D/3D playback, variation picking (`id_1..N`), occlusion muffling, ambience |
| `Fx` | `src/autoload/fx_manager.gd` | Pooled impacts, decals, tracers, muzzle lights |

### 3.4 Physics layers

| Bit | Name | Used by |
|---|---|---|
| 1 | world | Static map geometry (blocks movement, bullets, sight) |
| 2 | body_attackers | Attacker movement bodies |
| 3 | body_defenders | Defender movement bodies |
| 4 | hitbox | Per-limb `Area3D` hitboxes (bullets only) |
| 5 | trigger | Bombsites, buy zones, callout zones |
| 6 | prop | Dropped weapons, the charge, dynamic props |

Decision: **teammates do not collide** (each team masks only the enemy body
layer). Avoids bot gridlock in chokepoints and friendly body-blocking;
enemies still block each other.

### 3.5 Core runtime objects

- `Combatant` — movement physics (Source-style ground/air acceleration,
  friction, jump stamina, crouch & crouch-jump, walk), vitals (health, armor,
  helmet, kit), `Inventory`, hitboxes, third-person `CharacterModel`.
- `WeaponInstance` — per-gun runtime state: magazine/reserve, fire cooldown,
  reload/draw timers, recoil index & recovery, accumulated inaccuracy.
  Ticked by the owner; emits shots that `Ballistics` resolves.
- `Ballistics` — ray casts against world + hitboxes, wall penetration via
  surface metadata, range falloff, `DamageModel` resolution.
- `MatchManager` — round state machine, spawning, economy, scoring, side swap.
- `Bomb` — carried / dropped / planting / planted / defusing / exploded.
- `TeamTactics` (AI) — per-team round plan (site choice, roles), shared
  knowledge of enemy sightings; `BotBrain` executes individual behaviour.

### 3.6 Rendering & performance strategy

- Map geometry is generated, then **merged per material per spatial chunk**
  (few draw calls, still frustum-cullable). Box-projected world-space UVs, so
  textures have consistent texel density without triplanar shader cost.
- Collision: one `StaticBody3D` per surface type with box shapes (cheap,
  exact), surface type stored as metadata for FX/footsteps/penetration.
- Large walls get `OccluderInstance3D` box occluders (occlusion culling).
- Lighting: sun with PSSM shadows + local omni/spot lights; SDFGI/SSAO on
  desktop presets only; `GameSettings.quality_profile()` drives this so
  low/mobile tiers degrade gracefully.
- Physics at 60 Hz with physics interpolation; the first-person camera is
  top-level and placed in `_process` from the interpolated body transform,
  with mouse look applied every frame (no input latency from interpolation).

### 3.7 Testing strategy

`tools/run_tests.sh` imports the project then runs `tests/test_runner.tscn`
headless. It fails on any assertion failure **or** any engine `SCRIPT ERROR`.
Suites (grow per phase): core rules, map validation (geometry, spawns on
navmesh, all objectives reachable), movement physics, weapons
(fire/reload/recoil/damage), AI (bots reach sites, engage), match rules
(economy, round outcomes) and full simulated bot rounds. Visual checks are
screenshots rendered with Forward+ on a software Vulkan device (lavapipe)
under Xvfb (`tools/screenshot.sh`).

### Phase 1 — Architecture (done)

Delivered: project config (Jolt, Forward+/mobile, layers, navigation cell
sizes, display stretch for multi-resolution), folder structure, autoloads
(`Events`, `GameSettings`, `Audio`, `Fx` stub), shared types (`GameConst`,

### Phase 2 — Map foundation (done)

**MapBuilder** (`src/map/map_builder.gd`): playable space is declared as
zones on a 1 m grid; every non-walkable cell touching a walkable one becomes
solid, so walls are watertight by construction. Door zones in a 1-cell wall
gap get automatic lintels; roofed zones get ceilings, and roof height
changes get headers/edges (no light leaks). Explicit primitives: `box`,
`box_xf`, `cylinder`, `ramp` (low edge sunk below the floor so bodies meet
the slope, not an edge), `stairs` (visual steps + smooth collision ramp),
`clip` (movement-only blockers), lights and `Label3D` signage. Output is
merged per material per 40 m chunk with world-space UVs and baked contact AO
in vertex colours; collision is grouped per surface type; large solids feed
one `ArrayOccluder3D`. `MapProps` provides prefabs (crates, containers,
boxcar, flatbed, forklift, barrels, pallets, jersey barriers, windows,
doors, lamps, railings, pipes, I-beams, shelves, machines).

**Sawtooth** (`src/map/layouts/sawtooth_layout.gd`), ~88 x 81 m:
attacker yard (south) → Truck Lane → Long Rail (Long Doors choke) → A;
Mid street with gatehouse → Pump House stairs (Short A) / Workshop (B
Short); Scrap Lane → Tunnels → Coal Yard → B Main; defender court (north)
with A Gate, Back Hall and Mid Gate. Site A: raised loading platform with
dispatcher hut, boxcar, walkway, ramp and stairs. Site B: sawtooth-roofed
foundry with furnace, ladle, press and a mezzanine; south-facing glazing
throws sun shafts across the site. Markers: 8 spawns/team, buy zones, 5
attack routes, 11 defender holds, retake rallies, 6 plant spots, post-plant
and lurk spots, 20+ callout regions, radar data.

**GameMap**: sun (4-split PSSM), procedural sky, AgX tonemapping, SSAO/
SDFGI/glow/fog per quality preset, navmesh baked at load (~60 ms).

Measured (navmesh paths at rifle speed 5.7 m/s): attackers reach A in
14.2 s / B in 13.9 s; defenders reach A in 6.8 s / B in 4.9 s. Routes:
A Long 96 m, A Short 75 m, B Tunnels 79 m, B Short 70 m, Mid 57 m.

Tests: `test_map` (10) — build, spawns valid & clear, sites reachable with
timing bounds, every route leg and every marker on/reachable via navmesh,
watertight (horizontal rays from every marker never escape), floor under
every walkable cell, callouts, surfaces. Visual check: 19 viewpoint
screenshots rendered with Forward+ (lavapipe).

### Phase 3 — Player controller (done)

`Combatant` (`src/actors/combatant.gd`, CharacterBody3D + cylinder hull):
Source-style ground accel (6.5) / friction (5.2, stop speed 2 m/s), air
accel with 0.8 m/s wish cap, jump 6.6 m/s (apex 1.09 m), crouch-jump tuck
(apex ~1.39 m: 1.15 m crates need a crouch-jump, 1.45 m boxes are
unreachable), smooth crouch with headroom check, walk (52%, silent), crouch
(34%), jump fatigue, coyote time, 0.3 m automatic step-up, fall damage above
12.5 m/s, surface-aware footsteps (+ AI noise events), damage/armor/death
via `DamageModel`. `PlayerBrain` is the only class reading `Input`
(discrete actions are event-queued so mouse-wheel presses aren't lost).
`PlayerCamera` is top-level, positioned each frame from the interpolated
body transform with immediate mouse look, smoothed eye height, head bob,
strafe roll, landing spring, view punch and zoom.

Tests: `test_movement` (16) — acceleration time, stopping distance, walk/
crouch speeds, diagonal cap, jump & crouch-jump apex, crate rules, low
ceiling crouch lock, air-control bound, fatigue, fall damage, freeze time,
footsteps (running vs walking), 25 cm step-up vs 45 cm ledge, and walking
all five attack routes on the real map via navmesh paths (10–16 s each,
never stuck). Runner uses `--fixed-fps 60` (deterministic, faster than
real time).

### Phase 4 — Weapon systems (done)

**Data**: `WeaponData` resources in `data/weapons/` (edit in the
inspector): Field Knife, P9 Service Pistol, Mk.50 Hand Cannon, Vx-9 SMG,
Breacher-12 pump shotgun, Ravager AR (attackers), Sentinel Carbine
(defenders), Longbow bolt sniper (2 zoom levels), Breach Charge. Each defines
damage, armor penetration, range falloff, wall penetration, fire rate,
magazine/reserve, reload (magazine or shell-by-shell), draw time, move speed,
a CS-style inaccuracy model (stand/crouch/move/air/per-shot/recovery,
scoped) and recoil parameters from which a **deterministic spray pattern**
is generated (learnable, first shot always on target).

**Runtime**: `WeaponInstance` (ammo, draw/reload state machine, cooldown,
spray index & accuracy recovery, reload sound cues, pump/bolt cues).
`WeaponController` (Combatant component): slots, switching (number keys,
wheel, last-weapon), semi/auto fire, pellets, spread cone, aim punch from the
pattern (camera shows `view_punch` of it, so players pull down to
compensate), auto-reload, scope zoom with slower movement, knife slash/stab
with backstab x2.8, speed limit per weapon.
`Ballistics`: hitscan against world + props + per-limb `Hitbox` areas,
range falloff, armor via `DamageModel`, penetration through wood / thin
metal using exit-point back-tracing (concrete/brick stop bullets), melee
fan trace.

**Presentation**: `CharacterModel` — procedural soldier per team (khaki/
orange Breachers with balaclava & goggles, navy/blue Wardens with helmet),
walk cycle, crouch, air tuck, aim pitch, two-bone arm IK onto the weapon,
death fall, hitboxes on animated limbs, third-person muzzle flash; the
local player's body renders shadows only. `WeaponModels` — original
primitive-built guns with Mag/Bolt/Pump/Slide parts and Muzzle/Eject/Fore
markers. `ViewModel` — tiny-scale rig (never clips walls) with look sway,
bob, recoil spring, draw, magazine swap animation, shell reloads, pump/bolt
cycling, pistol slide lock, knife arcs, muzzle flash quads + light,
ejected casings. `Fx` — pooled decals, dust/sparks/chips/blood bursts,
tracers, flash lights, casings with bounce + tink. `PlayerHUD` — dynamic
crosshair from real inaccuracy, hit markers (red on kill, ping on
headshot), health/armor/ammo panels, reload bar, scope overlay, damage
vignette. Camera/viewmodel springs use fixed substeps (`Spring`).

Tests: `test_weapons` (15) — data validity & sounds & balance invariants
(Ravager one-taps helmets, Sentinel doesn't), ammo/reload timing, shell
reload + interrupt, semi vs auto cadence, hit groups by aim point, helmet
absorption, range falloff, wood penetration vs concrete stop, recoil climb
and recovery, spread by stance, switching/draw/speed/scope, knife +
backstab, shotgun pellets, kill events, empty-mag auto-reload.
Visual check: first-person screenshots with rifle and pistol, kill
confirmed on a target dummy (`tools/game_shot.sh ... --dummies --fire`).

### Phase 5 — Combat AI (done)

Bots write the same `CombatIntent` as the player (no cheating on movement,
spread or recoil).

- **Perception** (`BotBrain._sense`, every 90–140 ms): view cone
  (difficulty FOV) + line-of-sight rays to chest, head and legs; hearing
  through `Events.noise_emitted` (footsteps, jumps, landings, gunshots);
  shared sightings via `TeamTactics`.
- **Combat**: reaction delay from acquisition, initial aim error that decays
  with a settle time, head/chest choice, recoil compensation (fraction of
  aim punch), firing only when on target; automatic weapons fire range-based
  bursts (spray close, bursts mid, taps long), semi-autos tap, snipers scope
  and wait to settle; rifles stop to shoot at range (counter-strafe),
  close-range strafe-shooting; crouch at range; hold the angle after losing
  sight; pistol fallback when the primary runs dry; reload when safe; seek
  hidden navmesh cover when losing a duel.
- **Movement**: `BotNav` path following with periodic repath and stuck
  recovery (jump → sidestep → repath); walking (silent) near staging points;
  **angle checking** — while moving, bots pre-aim known enemy positions that
  are actually in line of sight.
- **Team tactics** (`TeamTactics`): attackers pick a site (avoiding
  repeats), split over its routes (+ optional lurker), stage at the last
  approach point and execute together (all staged, 9 s after the first
  arrival, or 55 s), spread to clear the site; plant/fetch/guard hooks for
  the charge (wired in Phase 6). Defenders take site holds (2 A / 2 B /
  1 mid), rotate on 2+ sightings at a site, retake via rally points and pick
  a defuser after a plant. Hunt mode breaks stalemates.
- **Difficulty** (`BotProfile`): Easy / Normal / Hard / Expert scale reaction
  (0.6 → 0.15 s), turn speed, aim error and settle, headshot chance, recoil
  compensation, FOV, burst length, crouch/strafe skill, aggression.

Tests: `test_ai` (5) — walls block perception, normal bot kills an exposed
enemy at 20 m (~0.8–1.1 s), reaction times respected and ordered by
difficulty, cover point hidden from the threat, and three full 5v5 bot
rounds on Sawtooth: decisive eliminations, attackers reach their site, no
bot stalls on a moving task. Outcomes vary by seed (one run: attackers
won 2 of 3; another: defenders 3 of 3). Early mid duels (~3–5 s) are common;
side balance is revisited with the full objective in Phase 6/8.

### Phase 6 — Game rules (done)

- **MatchManager** (`src/game/match_manager.gd`): phases FREEZE (6 s, buy) →
  LIVE (1:55) → PLANTED (40 s) → ROUND_END (5 s) → HALFTIME → MATCH_END.
  First to 7, max 12 rounds, sides swap after round 6 (scores swap with the
  squads, money resets, models re-skin). Survivors keep weapons/armor;
  the dead respawn with knife + P9. Win conditions: elimination (attackers
  need no survivors only if the charge isn't planted), time expiry,
  detonation, defuse.
- **Breach charge** (`Bomb`): carried by a random attacker, dropped on death
  or with G, picked up by walking over it; planting (3.2 s, hold fire/E with
  the charge in a site) and defusing (10 s, 5 s with kit, hold E within
  1.7 m) lock movement and cancel on release; accelerating beeps + blinking
  LED; explosion with radius damage, flash, scorch.
- **Economy** (`Economy`, `MatchConfig`): start $800, cap $16,000, win
  $3,250 (elim/time) / $3,500 (bomb/defuse), loss bonus $1,400 + $500 per
  consecutive loss (cap $3,400), attackers who survive a time loss get
  nothing, +$800 team bonus for planting, +$300 plant/defuse, kill rewards
  per weapon (knife $1,500, SMG $600, shotgun $900, sniper $100).
- **Buying** (`BuySystem`, `BuyMenu`): B in the buy zone during the first
  20 s; side-locked rifles, kevlar / kevlar+helmet (helmet-only upgrade
  $350), defuse kit (Wardens). Bots buy with team-aware logic
  (`BotBuyer`: pistol-round armor/upgrade, full buy, force buy, eco).
- **Dropped weapons** (`WorldWeapon`): physics props keeping their ammo;
  auto-pickup into empty slots, E to swap; dropped on death.
- **Scoring**: kills, assists (40+ damage), deaths, score, round MVP,
  kill feed with headshot/penetration markers.
- **UI**: `MatchHUD` (timer, scores, alive pips, money + change popups,
  charge status/bar, plant/defuse progress, kill feed, announcements, MVP,
  radar with spotted enemies and charge), `Scoreboard` (Tab), `BuyMenu`,
  `PauseMenu` (Esc, pauses the match) with `SettingsPanel`, `EndScreen`,
  `SpectatorCamera` (follow living teammates after death), `MainMenu`
  (live map backdrop, side + difficulty selection, settings).
- Bots: plant at authored plant spots, fetch dropped charges, guard post-
  plant spots, retake via rally points and defuse (closest defender).

Tests: `test_match` (6) — economy rules, buy rules (side locks, prices,
helmet upgrade, weapon replacement drop), planting (site + 3.2 s, release
cancels, movement lock), defuse 10 s / 5 s with kit, explosion radius
damage, and a full bot-only match (first to 4, swap after 3) asserting the
match ends, every round is awarded once, the halftime swap happens, the
charge gets planted, money stays within bounds and kills ≤ deaths.
Screenshots: freeze-time HUD, buy menu, main menu.

## 5. Decisions log

| # | Decision | Rationale |
|---|---|---|
| D1 | Godot 4.7.2 + GDScript | Requested engine; latest stable; GDScript keeps iteration fast and exports to mobile without .NET. |
| D2 | Jolt physics | Default-quality 3D physics in 4.7, stable character collision, fast queries. |
| D3 | Intent-driven Combatant shared by player & bots | Identical rules, testable, mobile-ready input. |
| D4 | Procedurally generated textures/audio committed as files | No licensing risk, fully original, reproducible; files (not runtime generation) keep load fast and mobile-friendly. |
| D5 | Map built from a declarative layout script at load time | No editor needed to author; geometry, collision, navmesh, markers and radar all derive from one source. |
| D6 | Teammates don't collide | Prevents bot traffic jams; common in modern tactical shooters. |
| D7 | Game lives in `breach-line/` subfolder | Repository already contains an unrelated Astro site; keep them independent. |
| D8 | Cylinder movement hull, body never rotates | Flat bottom (stand on ledges like Source), round sides slide smoothly; yaw is view-only. |
| D9 | Ramps under stairs + automatic 0.3 m step-up | Smooth stair motion and navmesh, robust to small lips. |
| D10 | Explicit texture import settings (`tools/fix_imports.py`) | Runtime-created materials bypass the editor's 3D/normal-map detection; without this textures had no mipmaps or VRAM compression. |
| D11 | Physics 60 Hz + interpolation; camera top-level in `_process` | Smooth on high-refresh displays without adding look latency. |
| D12 | Deterministic recoil patterns generated from a few parameters | Skill-based spray control; tuning stays readable in the inspector. |
| D13 | Tiny-scale viewmodel instead of a second viewport | No wall clipping, no extra render pass or shadow cost (mobile-friendly). |
| D14 | Hitboxes are `Area3D`s on their own layer, parented to animated limbs | Bullets query them; movement never collides with them; crouch/aim change the target. |
| D15 | Bots use the shared intent + map-authored tactical markers | Fair bots, predictable tuning; markers double as level-design documentation. |
| D16 | Bots "check angles" toward authored enemy positions while moving | Without it, defenders won every mid crossing for free; makes duels fair and CS-like. |

## 6. Known issues

- **Side balance**: bot-only simulations currently favour the defenders
  (e.g. 5 of 6 rounds in one test match); long sightlines (Long Rail ↔ A
  site, mid ↔ gatehouse) favour stationary holders. To be measured over
  many matches and tuned in Phase 8.

- Software-rendered screenshots (lavapipe) run at ~1–2 fps; real GPU
  performance not yet profiled (Phase 8).
- Some props are simple primitives (workshop car, forklift) — Phase 7.
- Large unique texture features (asphalt patches) can repeat visibly over
  wide areas — consider decals/UV rotation in Phase 7.

### Bugs found and fixed
- `Rect2i.get_center()` returns integers: odd-sized collision boxes were
  shifted 0.5 m, leaving holes in floors/walls (caught by watertight and
  floor-coverage tests).
- Navigation regions sync asynchronously: queries right after baking
  returned the origin. `GameMap.await_navigation_ready()` waits (real-time).
- Idle bodies alternated on/off floor each tick, swallowing jump presses —
  keep a small downward velocity on the ground.
- Zero-thickness ramp edges read as 46° walls for the cylinder hull.
- A texture imported mid-write was marked invalid; reimport + explicit
  import settings.
- Camera/viewmodel springs (explicit Euler) exploded at very low frame
  rates, flinging the camera 26 m up — now integrated with fixed substeps.
- Test runner hung when a suite failed to compile; it now reports and
  continues.
