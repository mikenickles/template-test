# Breach Line — Development Log

Original round-based tactical FPS (Godot 4.7, GDScript). One map, two teams,
bomb objective, economy, bots. This file is the single source of truth for
architecture, decisions, phase status, known bugs and next steps.

---

## 1. Quick start

| Task | Command (run from `breach-line/`) |
|---|---|
| Play | `godot --path .` (or open `project.godot` in the Godot 4.7 editor and press F5) |
| Run tests | `tools/run_tests.sh` (optional filter: `tools/run_tests.sh test_map`) |
| Regenerate textures | `python3 tools/texgen.py` |
| Regenerate sounds | `python3 tools/sfxgen.py` |

Requirements: Godot **4.7.x** (standard build, not .NET). The project uses the
Jolt physics engine (built into 4.7) and the Forward+ renderer on desktop;
`rendering_method.mobile` is set to `mobile` for future phone builds.

Default controls: WASD move, mouse look, Space jump, Ctrl/C crouch, Shift
walk, LMB fire, RMB alt-fire/scope, R reload, E use (plant/defuse/pick up),
G drop, 1-5 slots, Q last weapon, wheel cycle, B buy menu, Tab scoreboard,
Esc pause.

## 2. Game design summary

- **Teams**: *Breachers* (attackers, carry the breach charge) vs *Wardens*
  (defenders). 5v5: the player plus four bots against five bots.
- **Round**: freeze/buy time → live (1:55) → optional bomb phase (40 s fuse)
  → round end. Attackers win by eliminating defenders or detonating the
  charge; defenders win by eliminating attackers before a plant, by running
  out the clock, or by defusing.
- **Match**: first to 7 round wins (max 12 rounds), sides swap at halftime
  (after round 6) with money reset.
- **Economy**: start money, win/loss rewards with escalating loss bonus,
  per-weapon kill rewards, plant/defuse bonuses, money cap.
- **Map**: *Sawtooth* — an original decommissioned rail-freight yard and
  foundry (sawtooth-roofed factory halls). Two bombsites (A: rail platform,
  B: foundry hall), mid street, long route, catwalk short route, culvert
  tunnel, defender rotations.
- All names (teams, weapons, map) and all content (geometry, textures,
  sounds) are original and generated by this repository's code.

## 3. Architecture

### 3.1 Principles

1. **One simulation for humans and bots.** A `Combatant`
   (`CharacterBody3D`) is driven only by a `CombatIntent` (move vector,
   absolute view angles, buttons). `PlayerBrain` fills the intent from
   keyboard/mouse; `BotBrain` fills it from AI. Movement, weapon handling and
   rules can't diverge between them, and bots are "fair" by construction.
2. **Input abstraction for mobile.** Only `PlayerBrain` touches `Input`.
   A future touch-controls source writes the same `CombatIntent`.
3. **Data-driven content.** Weapons are `WeaponData` resources
   (`data/weapons/*.tres`); the map is a declarative layout script consumed
   by a reusable `MapBuilder`; match rules live in a `MatchConfig` resource.
4. **Event bus, not webs of references.** Systems talk through the `Events`
   autoload (kills, damage, round flow, objective, UI announcements). HUD,
   audio, AI hearing and stats subscribe independently.
5. **Pure rules are separate from nodes** (`DamageModel`, `Economy`,
   recoil/spread math) so they are unit-testable headless.
6. **Everything testable headless.** `tests/` runs under `--headless` and
   includes full bot-vs-bot round simulations.

### 3.2 Folder structure

```
breach-line/
  project.godot            engine config (Jolt, Forward+, layers, autoloads)
  DEVELOPMENT.md           this file
  assets/
    textures/<mat>/        generated PBR sets (albedo/normal/rough)
    fx/                    generated sprites (muzzle flash, decals, smoke)
    audio/<category>/      generated WAVs (weapons, impacts, footsteps, ...)
  data/
    weapons/*.tres         WeaponData resources (tuning lives here)
  scenes/                  top-level scenes (main menu, game)
  src/
    autoload/              Events, GameSettings, Audio, Fx singletons
    core/                  GameConst, CombatIntent, DamageInfo, DamageModel
    map/                   MapBuilder, materials, props, MapInfo, layouts
    actors/                Combatant, Hitbox, CharacterModel, Inventory
    player/                PlayerBrain, PlayerCamera
    weapons/               WeaponData, WeaponInstance, Ballistics, viewmodel,
                           procedural weapon models
    fx/                    effect nodes (muzzle flash, tracer, impact)
    ai/                    BotBrain, perception, aim, TeamTactics
    game/                  MatchManager, Bomb, Economy, BuySystem, records
    ui/                    HUD, buy menu, scoreboard, radar, menus
  tests/                   headless test runner + suites
  tools/                   texgen.py, sfxgen.py, run_tests.sh, screenshots
```

### 3.3 Autoload singletons

| Name | File | Responsibility |
|---|---|---|
| `Events` | `src/autoload/events.gd` | Global signal bus |
| `GameSettings` | `src/autoload/game_settings.gd` | Persisted settings (`user://settings.cfg`), input action registration, audio buses, quality presets |
| `Audio` | `src/autoload/audio_manager.gd` | Pooled 2D/3D playback, variation picking (`id_1..N`), occlusion muffling, ambience |
| `Fx` | `src/autoload/fx_manager.gd` | Pooled impacts, decals, tracers, muzzle lights |

### 3.4 Physics layers

| Bit | Name | Used by |
|---|---|---|
| 1 | world | Static map geometry (blocks movement, bullets, sight) |
| 2 | body_attackers | Attacker movement bodies |
| 3 | body_defenders | Defender movement bodies |
| 4 | hitbox | Per-limb `Area3D` hitboxes (bullets only) |
| 5 | trigger | Bombsites, buy zones, callout zones |
| 6 | prop | Dropped weapons, the charge, dynamic props |

Decision: **teammates do not collide** (each team masks only the enemy body
layer). Avoids bot gridlock in chokepoints and friendly body-blocking;
enemies still block each other.

### 3.5 Core runtime objects

- `Combatant` — movement physics (Source-style ground/air acceleration,
  friction, jump stamina, crouch & crouch-jump, walk), vitals (health, armor,
  helmet, kit), `Inventory`, hitboxes, third-person `CharacterModel`.
- `WeaponInstance` — per-gun runtime state: magazine/reserve, fire cooldown,
  reload/draw timers, recoil index & recovery, accumulated inaccuracy.
  Ticked by the owner; emits shots that `Ballistics` resolves.
- `Ballistics` — ray casts against world + hitboxes, wall penetration via
  surface metadata, range falloff, `DamageModel` resolution.
- `MatchManager` — round state machine, spawning, economy, scoring, side swap.
- `Bomb` — carried / dropped / planting / planted / defusing / exploded.
- `TeamTactics` (AI) — per-team round plan (site choice, roles), shared
  knowledge of enemy sightings; `BotBrain` executes individual behaviour.

### 3.6 Rendering & performance strategy

- Map geometry is generated, then **merged per material per spatial chunk**
  (few draw calls, still frustum-cullable). Box-projected world-space UVs, so
  textures have consistent texel density without triplanar shader cost.
- Collision: one `StaticBody3D` per surface type with box shapes (cheap,
  exact), surface type stored as metadata for FX/footsteps/penetration.
- Large walls get `OccluderInstance3D` box occluders (occlusion culling).
- Lighting: sun with PSSM shadows + local omni/spot lights; SDFGI/SSAO on
  desktop presets only; `GameSettings.quality_profile()` drives this so
  low/mobile tiers degrade gracefully.
- Physics at 60 Hz with physics interpolation; the first-person camera is
  top-level and placed in `_process` from the interpolated body transform,
  with mouse look applied every frame (no input latency from interpolation).

### 3.7 Testing strategy

`tools/run_tests.sh` imports the project then runs `tests/test_runner.tscn`
headless. It fails on any assertion failure **or** any engine `SCRIPT ERROR`.
Suites (grow per phase): core rules, map validation (geometry, spawns on
navmesh, all objectives reachable), movement physics, weapons
(fire/reload/recoil/damage), AI (bots reach sites, engage), match rules
(economy, round outcomes) and full simulated bot rounds. Visual checks are
screenshots rendered with Forward+ on a software Vulkan device (lavapipe)
under Xvfb (`tools/screenshot.sh`).

## 5. Decisions log

| # | Decision | Rationale |
|---|---|---|
| D1 | Godot 4.7.2 + GDScript | Requested engine; latest stable; GDScript keeps iteration fast and exports to mobile without .NET. |
| D2 | Jolt physics | Default-quality 3D physics in 4.7, stable character collision, fast queries. |
| D3 | Intent-driven Combatant shared by player & bots | Identical rules, testable, mobile-ready input. |
| D4 | Procedurally generated textures/audio committed as files | No licensing risk, fully original, reproducible; files (not runtime generation) keep load fast and mobile-friendly. |
| D5 | Map built from a declarative layout script at load time | No editor needed to author; geometry, collision, navmesh, markers and radar all derive from one source. |
| D6 | Teammates don't collide | Prevents bot traffic jams; common in modern tactical shooters. |
| D7 | Game lives in `breach-line/` subfolder | Repository already contains an unrelated Astro site; keep them independent. |
